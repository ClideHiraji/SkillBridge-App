Triggered by tapping the Bell icon in the top nav. Click outside to dismiss.
🔔 Notification Popup
A floating dropdown card that appears below the Bell icon. Has a dark semi-transparent backdrop overlay. Clicking outside the card dismisses it.

Layout Specs
Position: Absolute, top-right aligned below Bell icon
Width: 320px (mobile: calc(100vw - 32px))
Max-height: 400px, overflow-y: scroll (scrollbar hidden)
Border-radius: 16px (--radius-lg)
Background: #FFFFFF
Shadow: 0 20px 60px rgba(0,0,0,0.15)
Z-index: 9999
Backdrop / Dismiss Behavior
• A full-screen transparent backdrop sits behind the popup (z-index: 9998)
• onClick on backdrop → close popup (set isOpen = false)
• Animated: popup slides down + fades in (translateY(-8px) → 0, opacity 0 → 1, 200ms ease-out)
• Unread count badge on Bell: red dot (8px circle, #EF4444), absolute top-right of Bell icon
• When all read: badge disappears
Notification Item Types
Each notification row follows a consistent structure with a colored dot indicating type and read state.
Dot Color System
🔵 #4F5BD5 (Brand) — Task updates, applications, new matches
🟢 #10B981 (Success) — Payment released, task completed
🟡 #F59E0B (Warning) — Deadline reminders, pending actions
⚪ #E5E7EB (Gray) — Already read / general info
Notification Categories

review"[Business] left you a ⭐⭐⭐⭐⭐ review"
States
Empty State: Show bell illustration + "You're all caught up! No new notifications." text, centered in popup body.

Loading State: 3 skeleton rows (gray shimmer rectangles) while fetching.
Figma Component: Create as "Notification/Popup" component with isOpen boolean variant. Create "Notification/Item" sub-component with type (task_match | payment | deadline | review) and isRead (true | false) variants.

05
Business Owner Flow — New Screens
Complete new flow for business users to post, manage, and advertise tasks/commissions
User Type Split: At Login/Register, user selects "Student" or "Business Owner". This determines which navigation and screens are shown. Business Owner routes are prefixed with /business/.
📊 Business Dashboard
/business/dashboard
Header: "Good morning, [Business Name]" greeting + Avatar (profile popup trigger) + Bell icon (notification popup trigger)
Stats Row: 3 horizontal stat cards — Active Tasks, Total Applicants, Completed Tasks. Use same StatCard component, icon color orange (#FF7B54).
My Active Tasks: Horizontal scroll row of task cards (compact variant). Each shows title, applicant count badge, deadline. Tap → Task Management screen.
FAB (Floating Action Button): Orange (#FF7B54) circle, "+" icon, bottom-right, 56×56px, radius-full. Tap → Post New Task flow. This is the primary CTA.
Bottom Nav: 4 items — Dashboard (home), My Tasks (briefcase), Messages (chat), Profile (user). Accent color: #FF7B54.
✍️ Post New Task / Commission
/business/post-task
Step Indicator: "Step 1 of 2" / "Step 2 of 2" top progress bar (2 segments, brand color fill). Step 1 = Task Details, Step 2 = Requirements & Budget.
Step 1 Fields: Task Title (text input), Category (chip selector grid — all 7 categories, tap to select), Task Description (multi-line textarea, 200 char limit shown), Deadline (date picker via Calendar UI).
Step 2 Fields: Commission Amount (₱ prefix input, numeric, required), Estimated Time (dropdown: 1-2h, 3-5h, 5-8h, 8-12h, 12h+), Skills Needed (text input with tag creation — type + enter adds a SkillTag), Max Applicants (number stepper, default 5).
Preview Screen: After Step 2, show a read-only preview of the task card as a student would see it. Buttons: [Edit] and [Post Task].
Success State: Full-screen success illustration + "Your task is now live! Students can start applying." + [View Task] button.
📋 My Tasks
/business/tasks
Tabs: Three horizontal tabs — Active | Pending Review | Completed. Underline tab style with orange accent.
Task List Item (Business View): Shows task title, category badge, applicant count pill ("3 applicants" in orange bg), days remaining, price. Tap → Task Applicants screen.
Swipe Actions (optional MVP note): Swipe left on item reveals Edit and Close Task actions.
Empty State: Illustration + "No tasks yet. Tap + to post your first task." with Post Task shortcut button.
👥 Task Applicants
/business/task/:id/applicants
Header: Back arrow + task title (truncated) + applicant count ("4 applicants").
Task Summary Card: Compact card at top showing price, deadline, category — collapsible.
Applicant Row: Avatar (initials) + Name + University + Rating (⭐ x.x, N reviews) + Skills preview (2 tags max). Two action buttons: [View Profile] [Accept].
Accept Confirmation: Bottom sheet modal — "Accept [Student Name]?" body + confirm button. After accept, task moves to "In Progress" status, other applicants get notified.
Status Badges: On applicant row — "Pending" (gray), "Accepted" (green), "Rejected" (red).
🧑‍🎓 View Applicant Profile
/business/applicant/:studentId
Same layout as Student Profile screen but in read-only mode (no edit buttons visible). Shows full bio, skills, rating, reviews.
Portfolio Section: Horizontal scroll row of work samples (image thumbnails with + Add button for student's side; view-only for business).
Sticky Bottom CTA (from applicants screen context): Two buttons — [Message Student] [Accept for Task].
Past Tasks Completed: Small count badge at top of profile ("12 tasks completed") adds credibility signal.
⚡ Active Task Management
/business/task/:id/manage
Assigned Student Card: Shows accepted student's avatar, name, rating, contact info, and "Message" shortcut button.
Progress Indicator: Status stepper — Applied → Accepted → In Progress → Done → Paid. Current step highlighted in brand orange.
Student Submits Work: When student marks task as done, a "Work Submitted" banner appears with [Review & Release Payment] button (brand-accent color).
Release Payment CTA: Shows commission amount prominently in green. Confirmation: "Release ₱[X] to [Student]?" with [Confirm] button.
Review Student: After payment, prompted to leave a star rating (1–5) + short review text. This data feeds Student's profile reviews.
🏢 Business Profile
/business/profile
Hero Section: Orange/accent gradient (#FF7B54 → #FF9B54). Business logo/avatar, Business Name, Category badge (e.g. "Food & Beverage"), Location.
Stats: Tasks Posted, Total Hired, Avg Rating (from student reviews). Displayed in a 3-column stats card same style as Earnings screen.
About Section: Business description, address (MapPin icon), website URL, contact email.
Reviews from Students: Scrollable review cards — student says how the experience was with this business. Adds trust for future student applicants.
Edit Button: Settings/Edit icon in header → Business Profile Edit screen.
✏️ Edit Business Profile
/business/profile/edit
Editable Fields: Business Name, Category (dropdown), Description (textarea), Address, Website, Contact Email, Business Logo (image upload area with dashed border).
Logo Upload: 80×80 square with dashed border, "Tap to upload" caption. Supports PNG/JPG preview after selection.
Save button: Primary button, sticky at bottom. "Saving..." loading state.
Figma Page Structure: Create a separate Figma page called "Business Owner Flow". Use a distinct orange (#FF7B54) header color for all business screens to visually distinguish from student screens. Business BottomNav has 4 items: Dashboard, My Tasks, Messages, Profile — using orange as the active state color.

Figma Build Notes
Instructions for assembling this spec in Figma
📄 Page Structure
Organize Figma file by pages
Page 1: 🎨 Design Tokens — all color swatches, typography samples, spacing, radius
Page 2: 🧩 Components — all reusable components in component library grid
Page 3: 🎓 Student Flow — all student screens in flow order (left to right)
Page 4: 🏢 Business Flow — all business owner screens in flow order
Page 5: 🔀 Shared Screens — Login, Register, Onboarding, Settings, etc.
Page 6: 💬 Overlays & Modals — Notification popup, Profile popup, Filter sheet, etc.
Page 7: 🗺️ User Flow Diagram — prototype connectors overview
📱 Frame Sizes
Use these exact frame sizes
Mobile screens: 390 × 844 (iPhone 14 size)
Bottom sheets: 390 × auto (content height), add corner radius 24px top only
Popup overlays: Notification = 320×auto, Profile mini-card = 220×auto
Top Nav bar: 390 × 56, background white, bottom shadow
Bottom Nav bar: 390 × 64, background white, top shadow
Scrollable content: Set frame "Clip content" ON, body starts at y=56 (nav height)
🎨 Color Application Rules
Consistent color usage across screens
Student nav active: #4F5BD5 (brand-primary)
Business nav active: #FF7B54 (brand-accent)
Student profile hero: #4F5BD5 solid
Business profile hero: gradient #FF7B54 → #FF9B54
Success states: #10B981 (green)
Error/danger: #EF4444 (red)
Warning/pending: #F59E0B (amber)
Page backgrounds: #F9FAFB (--neutral-50)
🔗 Prototype Connections
Key interactions to wire in Prototype mode
Bell icon → Open Overlay (Notification popup) → Dismiss on outside click
Avatar icon → Open Overlay (Profile mini-card) → Dismiss on outside click
Task Card → Navigate to Task Detail (push transition)
Accept Task button → Swap component (accepted banner state)
FAB (+) → Navigate to Post Task Step 1 (push up)
Filter icon → Open Overlay (Filter bottom sheet)
Log Out menu item → Open Overlay (confirm dialog)
BottomNav items → Navigate (no animation / instant)
Variable Modes Tip: Set up two Variable Modes — "Student" and "Business" — for the nav active color variable. This lets you switch the entire BottomNav accent from purple to orange by toggling the mode on the frame, rather than recoloring manually.
Empty States: Every list screen needs at least one empty state variant designed. This is commonly overlooked but critical for MVP polish. Screens that need empty states: Student Feed (no results), My Accepted Tasks, Business My Tasks, Messages, Notifications. Use a centered illustration + heading + CTA button pattern.
